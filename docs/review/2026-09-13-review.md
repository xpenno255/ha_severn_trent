# Severn Trent review and v1.9.0 validation — 13 September 2026

Reviewed v1.8.0 (`b64ac37`) and implemented the v1.9.0 fixes described in the changelog. Issue #30 reproduces because the weekly total had no reset timestamp. Explicit daily/weekly reset boundaries now pass tests using Home Assistant's recorder compiler. The new dated external statistic additionally solves delayed-day attribution and catch-up after downtime.

## Live evidence

Read-only website comparison confirmed the existing account balance, payment amount/date and all seven official readings. The website's daily graph was temporarily unavailable, so daily totals could not be independently compared with that view. Authenticated API validation confirmed the corrected seven-day arithmetic, daily interval timestamps/units and the new history reader. No account credentials or identifying account data are included in this report.

The public schema validates all 13 operations. Two official-reading operations remain deprecated. The advertised `POINT_IN_TIME` replacement fails on the live account with `KT-CT-4710: Unsupported aggregation interval`. Omitting aggregation or using `RAW_INTERVAL` returns interval consumption, not a cumulative official baseline. Retaining the working endpoint is therefore intentional; a replacement requires supplier support and live verification.

## Implemented improvements

- Correct period resets, seven-day average, UK dates, missing/invalid readings, unit conversion and estimate coverage.
- Persist dated daily consumption, import original-date statistics, backfill one year gradually, and replay older corrections without duplicating rows.
- Typed authentication/transport failures, verified reauthentication, key reuse and shared-key recovery.
- Select meters across properties and select water ledgers consistently; cache stable metadata and avoid duplicate authentication.
- Redacted diagnostics, latest-reading/history status, explicit credit/debit attributes and optional sustained high-usage comparison.
- Current Home Assistant recorder metadata, test workflow and public schema validator.

## Limits

- Minimum Home Assistant is now 2026.9; runtime and recorder tests use 2026.9.2.
- Daily import places a day's total in its final hour. Hourly charts are not a measured hourly usage profile.
- Backfill and corrections depend on supplier data availability. Missing historical days cannot be reconstructed from weekly/monthly estimates.
- The deprecated official-reading API remains a supplier dependency. Estimates cannot establish an exact live odometer when the official baseline has no precise timestamp.
- Existing negative statistics are preserved. The new source can be selected without rewriting old sensor history.
